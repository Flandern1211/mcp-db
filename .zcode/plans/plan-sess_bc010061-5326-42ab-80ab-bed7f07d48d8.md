## Context
现在「访问令牌」和「管理授权」都按单条工具授权展开，`qa-nonprod` 有两项工具就出现两次。目标是让令牌页回答「能管哪些数据源」，让「管理授权」回答「在这个数据源上能做什么」。Agent 名称仍只是标签，授权属于具体令牌；同名令牌按短标识区分，不合并、不限制签发。完整令牌仍只在签发时显示并可复制。

**视觉基线**：采用你发的两张截图对应的 Nexus 管理台，保留现有蓝白配色、中文系统字体、等宽工具名和弹窗样式，只调整令牌列表及相关弹窗。代码以 `develop` 的 `3d4e3d1` 为起点；不把运行中镜像视为与该提交完全等同。开工先在隔离环境运行基线、核对截图并将位置与验收描述写入任务文件；不动现有实例的数据。

## 实施
1. **T-17｜数据源分组与原子保存（同一任务，共享保存契约）。** 更新 `SPEC.md`、`CHANGELOG.md` 和任务记录：令牌本身不改，管理员可单独修改它的工具授权；数据源分组不是新的权限。`src/transport/admin_assets/app.js` 将「授权」列改为「授权数据源」，按 `source_id` 去重，只显示数据源。弹窗里每个数据源一张可展开的卡片，卡内多选工具、按工具配置策略；新增先选数据源，取消最后一项时提示保存会移除该源。保留已授权但当前不可用的项，标明归档、无路由或连接配置停用，允许显式取消，不静默删除或新增不可用项。新增工具默认采用当前路由策略；既有策略不因展开或保存其他项而改变。
2. **增加一个数据源级保存接口，不改表或 MCP 契约。** 在 `src/transport/admin.rs` 增加 `PUT /admin/api/tokens/{id}/sources/{source_id}/grants`，复用现有读取接口、会话和 CSRF 校验。提交打开编辑时的工具/策略快照及最终集合，`[]` 明确表示清空。`src/state/store.rs` 用一个 SQLite 写事务校验当前快照、令牌、改动项及路由限制，按差异写入授权、审计，并使对应被撤销或改策略工具的未消费审批失效；未改工具、其他数据源、其他令牌和已消费记录不动。无效项整组拒绝；快照过期返回 `409`，提示重新加载；网络结果未知先刷新核对，不自动重试。保留现有逐条 API/CLI、审批消费前复核、生产普通写入限制和 `list_sources` 规则。
3. **T-18｜签发后复制（可独立验收）。** 在 `src/transport/admin_assets/app.js` 复用「复制令牌」「复制请求头」。签发成功立即显示明文，不等列表刷新；关闭后独立刷新。只有剪贴板确认写入成功才提示已复制；失败时提示手动选中复制，清理回退用的临时输入框。列表、刷新和重新打开管理授权都不再提供明文。两项工作都触及 `app.js`，串行委派和复核，避免覆盖；不新增依赖或调整其他页面。

## 验证与交付
- **显示与编辑**：用截图中的两源、三工具结构和同名令牌夹具，确认列表只出现两个源标签、同源只出现一张卡、工具与策略正确，不影响另一枚令牌；窄屏和键盘可用。
- **保存与拒绝**：一次点保存只发一次请求；刷新后验证勾选、取消、改策略均已落库。通过 `tests/admin_http.rs` 和状态库测试覆盖混合合法/非法项全不生效、旧快照冲突、缺 CSRF、生产和停用约束、审计与审批作用域。清空最后一项后，验证界面和该令牌下一次 `list_sources` 都不再列出该源，未授权工具仍被拒绝。
- **复制**：在隔离入口用临时令牌验证成功反馈、两种剪贴板路径都失败时不误报、列表刷新失败不妨碍保存明文、关闭后不能再次获取。证据不包含令牌明文或完整请求头。
- 运行 `scripts/verify.sh fast`、JS 语法检查，并用干净的本机入口、临时状态库和测试数据复验。由未参与实现的 agent 或你确认可见效果；无独立验收就保留「待验收」。任务分支和证据分开记录，不动现有数据、不合并、不推送。

**不做**：独立 Agent 身份、同名唯一限制、历史令牌明文找回或跨数据源一键保存。
