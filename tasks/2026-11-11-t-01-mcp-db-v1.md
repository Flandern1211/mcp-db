## 1. 范围

做什么：

- 配置与鉴权：每 agent × source 的 `readonly` / `readwrite` / `approval`；token 只存哈希。
- 四个驱动（PostgreSQL、MySQL、SQLite、SQL Server）与双连接池。
- MCP 工具：`list_sources`、`list_tables`、`describe_table`、`explain_query`、`execute_sql`。
- 执行保护：参数绑定、`max_rows` 截断、语句超时、审计。
- 审批：每条写语句确认；elicitation 优先，CLI 待批队列兜底。
- HTTP transport、管理接口、CLI 与启动入口。

不做什么：

- 限时授权、`session` 模式、`revoke`、`tools/list_changed`、Web 页、IM。
- 逻辑污染防护、回滚；Oracle 与 NoSQL。

## 2. 验收例子

1. `readonly` agent 写库被只读账号拒绝，数据和 schema 不变。
2. `readwrite` agent 的写语句直接落库。
3. `approval` + elicitation：accept 后执行，decline 后不执行。
4. `approval` 无 elicitation：写调用挂起，CLI 批准后执行；拒绝或超时不执行。
5. 参数、截断、超时、审计、管理面隔离、配置校验按 SPEC 的 AC 逐条验证。

## 3. 计划与风险

步骤：配置/鉴权/存储 → 驱动与连接池 → 工具与执行保护 → 审批与 CLI → 测试与示例。

风险：四个真实数据库无法在本机全部集成验证；elicitation 依赖客户端能力；SQLite 无语句超时。

## 4. 测试证据

- `bun run typecheck`：通过。
- `bun test`：35 个测试通过，覆盖 SQL 分类、配置校验、状态库、审批队列、SQLite 的只读/读写/审批三模式、Streamable HTTP 与鉴权。
- CLI 冒烟：`serve` 启动成功；无 token 访问 `/mcp` 返回 401；agent token 访问 `/admin/approvals` 返回 401；admin token 返回 200。
- 真实数据库集成（`bun run scripts/real-integration.ts`，Docker 临时实例）：
  - PostgreSQL（`pgvector/pgvector:pg16`）：DDL、写入、参数绑定、`listTables`、`describeTable`、只读账号拒绝写入、语句超时 302ms 均通过。
  - MySQL 8.4：同上全部通过，语句超时 307ms。
  - SQL Server：镜像下载停滞，未执行，见缺口。
