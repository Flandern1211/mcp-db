## 1. 范围

- 开工前确定 TLS 终止、受信代理、公开地址、Origin allowlist 和 admin 登录方式。
- 默认仍 loopback；显式远程模式必须同时具备 TLS/认证/网络控制。
- admin 会话使用 HttpOnly/SameSite/HTTPS Secure cookie 与 CSRF；agent 不能访问管理 API。
- 实现 token/profile/route/审批/归档恢复所需最小管理面，不扩展多管理员角色。

## 2. 验收例子

1. 非本机监听缺必需安全配置时启动失败，默认 loopback 保持可用。
2. 错误 Origin、非受信代理头和缺 CSRF 的 admin 写请求被拒绝。
3. agent token 无法访问任何 admin API；从非数据库主机经 TLS 访问多个 source 成功。

## 3. 计划与风险

- Bug 根因检查：不适用。
- 设计依据：SPEC 1、2、4、6；实现前固定远程入口设计。
- 步骤：安全配置 → proxy/origin → admin session/CSRF → 管理 handlers → TLS E2E。
- 拆分结论：远程入口与管理会话必须成组交付，避免裸露半成品。
- 并行判定：依赖控制面服务契约，串行。
- 风险：代理信任与 cookie 混淆；默认拒绝并只接受显式代理来源。
- 第一性原理检查：非本机可达性不能降低管理边界。
- 对抗性审查：覆盖伪造转发头、跨站请求和 agent/admin token 混用。
- 奥卡姆检查：不做组织、多角色或外部身份提供商。
