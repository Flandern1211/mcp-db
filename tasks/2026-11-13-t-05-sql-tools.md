## 1. 范围

- 先做 parser/首批方言与语句支持 spike，再实现 `query_sql`、`mutate_sql`、`execute_ddl`。
- fail-closed 拒绝跨类、多语句、未知、数据库级管理与执行型 explain；退役 `execute_sql`。
- 保持参数绑定和显式结果截断，不把截断描述为扫描限制。
- 不实现审批状态机或 profile 硬限制。

## 2. 验收例子

1. 四方言支持集中的合法单语句进入正确 tool，交叉调用在驱动前拒绝。
2. 多语句、解析失败、管理语句、写 CTE 和执行型 explain 均不触发外部执行。
3. 绑定参数不改变 SQL 结构，超限结果显式 `truncated`。

## 3. 计划与风险

- Bug 根因检查：不适用。
- 设计依据：SPEC 3.4、5.1；开工前把 parser、支持矩阵和 `CALL/EXECUTE` 边界补入基线。
- 步骤：spike → 机器可读 tool schemas → 方言策略 → drivers → 测试。
- 拆分结论：审批与资源限制分别由 T-06/T-07 独立验收。
- 并行判定：串行依赖 T-04；会与 T-06/T-07 共享执行路径。
- 风险：parser 覆盖与方言漂移；只开放有测试证明的语法。
- 第一性原理检查：不能确认类别就不能执行。
- 对抗性审查：覆盖注释、CTE、等价语法和间接执行。
- 奥卡姆检查：不保留兼容 alias。
