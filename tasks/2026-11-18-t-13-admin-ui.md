## 1. 范围

做什么：

- 以 v1 TypeScript 管理台为设计基线（`src/admin/ui/index.html`、`app.css`、`app.js`，取自提交 `da0bf14`，参考副本在 `D:/Project/mcp-db-wt/old-admin-ui/`），把 Rust admin 改成同样的中文 SPA：左侧导航 概览 / 访问令牌 / 待批请求 / 审计日志 / 数据源，复用其布局、配色、组件与交互。
- 静态资源内嵌进 Rust（`include_str!`），由 admin listener 提供，无 CDN、外部字体、JS 框架或新依赖。
- 补齐 UI 所需的 JSON API 与 Store 读取方法：session/login/logout、overview、sources 列表/创建/归档/恢复、profiles 列表/创建、routes 列表/创建、tokens 列表/创建/撤销、grants 列表/新增/撤销、approvals 列表/批准/拒绝、audit 列表（agent/source/decision/limit/offset）。
- 保留 T-09 安全模型：一次性登录令牌、进程内 1h 会话、HttpOnly+SameSite=Strict cookie、会话绑定 CSRF（前端从登录响应拿 token，写请求带 `x-mcpdb-csrf`）、Host 回环校验、Origin 同主机校验（兼容 Ego 隔离 space 的 `Origin: null`）、agent Bearer 禁止访问。
- 安全响应头覆盖所有 admin 响应：CSP（仅同源脚本/样式）、nosniff、no-referrer、no-store。

不做什么：

- 不在 Web 编辑 DSN/明文凭证；数据源页展示 profiles 及其 credential_ref 引用即可。
- 不做远程管理、TLS、多管理员；不改 MCP/审批/建库状态机；不改 CLI 命令。

## 2. 验收例子

1. 在 Ego Lite 隔离 space 与普通浏览器均可完成一次性令牌登录；重放令牌、agent Bearer、缺 CSRF、跨主机 Origin 均被拒绝。
2. 概览显示 source/token/pending/审计计数；数据源页可创建/归档/恢复并看到 profiles/routes；令牌页可创建/撤销 token、增删 grants；待批页可批准/拒绝；审计页可按 agent/source/decision 过滤分页。
3. 视觉与 v1 管理台一致（中文导航、侧栏、卡片/表格、编辑弹层、toast），窄屏不溢出，无外部资源，页面不含凭证。
4. 现有 `tests/admin_http.rs` 全部保持通过，新增 JSON API 测试；全量 `cargo test` 与 clippy 通过。

## 3. 计划与风险

- 设计依据：v1 `src/admin/ui` 与 `src/admin/routes.ts`；Rust 现状 `src/transport/admin.rs`、`src/state/store.rs`。

- 兼容：保留旧服务端渲染路由会与 SPA 冲突；切换后更新/删除对应测试，但安全断言必须保留。
