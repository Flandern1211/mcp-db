## 1. 范围

做什么：

- 在现有服务端渲染结构（`src/transport/admin.rs`）上完善视觉与交互：登录页、仪表盘布局、导航、表格、空状态、操作按钮、时间显示、操作结果提示。
- 响应式与可访问性：窄屏可读、颜色对比、表单 label、焦点可见、按钮语义明确。
- 安全响应头：CSP（仅内联样式）、`X-Content-Type-Options`、`Referrer-Policy`、`Cache-Control: no-store`。
- 保持现有路由、认证、会话、CSRF、Origin/Host 校验和状态机完全不变；不引入 JS 框架、外部字体、CDN 或新依赖。

不做什么：

- 不新增管理能力（token/grant/profile CRUD 仍走 CLI）；不做 SPA、远程访问、TLS 或主题系统。
- 不改 `Store`/`MCP` 行为与审计字段；不改 T-09 的安全边界。

## 2. 验收例子

1. 登录页与仪表盘使用一致的布局、排版和按钮样式；无外部资源请求，刷新与窄屏（约 375px）下内容不溢出。
2. 现有流程不变：登录、审批、归档、恢复、预留结算、登出式重定向仍工作；缺 CSRF/错误 Origin/agent Bearer 仍被拒。
3. 页面包含 `Content-Security-Policy`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Cache-Control: no-store`，且所有动态内容继续 HTML 转义。
4. 操作后显示成功/失败提示（不依赖 JS）；最近审计时间以本地可读格式展示。

## 3. 计划与风险

- Bug 根因检查：不适用。
- 设计依据：SPEC 1、3.6、5.1 与 `docs/PRD.md` 管理面边界；沿用 T-09 路由与安全模型。
- 步骤：样式与布局重构 → 页面结构与提示 → 响应头与可访问性 → 测试与截图复核。
- 拆分结论：仅前端呈现层，安全与状态机不拆。
- 并行判定：与 T-10 验收并行，改动只在 admin 呈现与对应测试。
- 风险：样式重构误改表单字段名或 action；用现有 `tests/admin_http.rs` 全量回归。
- 第一性原理检查：界面只呈现服务端已有事实，不新增授权或隐藏状态。
- 对抗性审查：内联样式注入、未转义字段、CSP 阻断、窄屏溢出。
- 奥卡姆检查：无构建链、无前端框架、无图标库。
